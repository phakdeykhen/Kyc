# KYC Production Readiness Report

**Overall: NOT_READY**

READY requires every critical component to be PRODUCTION_READY. This report is generated by `scripts/readiness_report.py` from `src/kyc/readiness.py`.

- **Document Capture**: Quality thresholds not calibrated on real phone captures.

- **Portrait Extraction**: Not measured on real cards.

- **Face Match**: Face calibration missing.
- **Liveness**: Liveness not validated against presentation attacks.

## Evidence and limitations

### Document Capture

Deterministic quality gate (blur, glare, brightness, shadow, coverage, perspective, resolution, multiple documents); 6 real KH ID photos: 2 accepted, 4 sent to recapture with correct instructions.
- Limitation: No live best-frame selection for document capture; the first accepted upload is processed.

### KH National ID

Adapter KH-NID-ADAPTER-2026.10.3; front MRZ (TD1) parsing; on 2 usable real cards the MRZ failed check digits or was not found, so both went to recapture/review (fail-safe).

### KH NSSF

Adapter on the shared Khmer label engine; synthetic fixtures only.

### KH Passport

Visual fields + TD3 MRZ engine; synthetic specimens only.

### OCR (Latin)

Tesseract 5 full-image OCR with a constrained numeric re-read.

### Khmer OCR

Full-page khm+eng OCR plus a Khmer-digit re-read. On 2 usable real KH IDs the Khmer name read at confidence 0.37-0.38 and sex, address and issue date were not found. Fixed: the Khmer digit model was silently skipped in the container image (Debian names it Khmer, not script/Khmer).
- Limitation: Low-confidence Khmer fields go to recapture/review, never PASS.

### MRZ

TD1/TD2/TD3 parsing, all check digits, visual-zone comparison; dedicated MRZ OCR pass.

### QR/Barcode

zxing decode, JWS/JSON/AAMVA/ICAO VDS parsing; signatures only against BARCODE_TRUST_STORE.
- Limitation: A decoded QR never counts as authenticity without a trusted signature.

### Document Authenticity

Authenticity accepted only from a verified chip or signed barcode; font, layout, text-region and pixel forensics are reported NOT_SUPPORTED; unverified documents go to REVIEW.
- Limitation: Every KH ID/NSSF session ends in MANUAL_REVIEW at best.

### Portrait Extraction

Portrait located by face detection with DOCUMENT_PORTRAIT quality gate; unusable portraits trigger recapture.

### Face Detection

OpenCV YuNet 2023mar with pinned hashes; selfie quality gate.

### Face Match

SFace 2021dec 1:1 cosine; uncalibrated policy always REVIEW; calibration framework (FAR/FRR/TAR/AUC, distributions) added; production refuses to start without a measured report.
- Limitation: Face match uses the uploaded selfie; liveness frames are bound to it, but the best liveness frame is not yet the comparison source.

### Liveness

Random single-use 4-step head-movement challenge, landmark geometry, replay and identity-continuity checks; uncalibrated policy is REVIEW at best; validation framework per attack type added.
- Limitation: 3D masks, AI-generated media and virtual-camera injection are NOT_SUPPORTED.

### Android Mobile

Only the development web capture page and the Verix front-end prototype exist; no native app or mobile SDK.

### iPhone Mobile

As Android.

### QR Handoff

Single-session client tokens (kst_) exist; no desktop-to-phone QR handoff screen, claim-once or live status channel.

### NFC Android

Server verification exists; the chip reader is only scripts/nfc_simulator.py.

### NFC iOS

As Android.

### CSCA

Trust store loads a CSCA folder and checks validity windows; no ICAO PKD/master-list import, update process or revocation (CRL) checking. Unknown issuers stay REVIEW.

### Fraud

Duplicate/replay/velocity within the tenant, MRZ/barcode/chip mismatches, metadata markers; forensic detectors NOT_SUPPORTED and reported as such.

### Risk Engine

Deterministic, versioned, tighten-only policy; FAIL > REVIEW > PASS; trace stored; uncalibrated face PASS now REVIEW; determinism test added.

### Manual Review

Separate reviewer tokens, REVIEWER/AUDITOR roles, reason codes, optimistic concurrency (409 CASE_CHANGED), approval blockers, audited views; case now shows check results, summary and timeline.

### RLS

Forced RLS on 25 tenant tables; live PostgreSQL isolation tests and scripts/security_check.py (24/24).

### Encryption

AES-256-GCM per data class with separate keyrings and rotation; keys come from environment secrets.

### Webhooks

Transactional outbox, HMAC-SHA256 with timestamp, retries, SSRF re-check per delivery.

### Workers

SKIP LOCKED document worker and webhook worker; OCR is the capacity limit (~24 docs/min on a laptop).

### GCP

Phase 19 not started; Dockerfile exists but the image build was never verified.

### Monitoring

Dependency health (/health/ready, /health/dependencies), Prometheus /metrics, alert rules (infra/monitoring).

### Backup

No backup configuration in the repository.

### Restore

Restore never tested.

### Repository Data Hygiene

The public repository contains real identity-card photos (ID/KhmerID, ID/NSSF) and personal data fragments in BUILD_PROGRESS.md.
